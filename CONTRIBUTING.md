# Contributing to S/Crawler

S/Crawler values executable behavior and inspectable evidence.

## Ground rules

1. Keep Level 0 as the supplied starting page.
2. Preserve explicit depth metadata through traversal.
3. Do not introduce fake data into operational UI paths.
4. Keep rendering, crawling, extraction, presentation, and action layers separable.
5. Tests must state what was actually executed.
6. Never report simulated or static inspection as a live PASS.
7. Prefer small, reviewable changes with reproducible evidence.

## Pull requests

Include:
- what changed;
- why;
- how it was tested;
- exact commands or workflow used;
- relevant output or screenshots for UI changes;
- any known limitations.
